## 1. 계약 — 실측 확인분 (2026-09-27)

```
GET   /api/users/{userId}/collections
        → CollectionResponse.previewPosterPaths: string[]   (최대 5, position ASC)

PATCH /api/collections/order                      { collectionIds: number[] }  ≤ 200  → 204
PATCH /api/collections/{collectionId}/movies/order { movieIds: number[] }      ≤ 500  → 204
```

**`npm run gen:api`를 먼저 돌린다.** `CollectionOrderRequest`·`CollectionMovieOrderRequest`가
생성분에 들어와야 한다 — 손으로 쓰지 않는다(상위 §4).

⚠️ **상한 200 / 500은 서버가 `@Size`로 막는다.** 초과하면 400이며 **부분 저장이 아니라 전부
실패**한다. §3.2의 전량 로드 크기를 이 값에 맞춘다.

  카드 오른쪽이 비었다). 폭 = (선반 안쪽 폭 − 간격 7×4) ÷ 5, 높이 2:3 — 390dp 기기에서 약 60×90.
  3배 밀도면 ~180px가 필요해 w92는 흐려지므로 **`PosterSize.SHELF`(w185)를 신설**했다.
  **대가: 홈 배경(w92)과 캐시 공유가 사라진다** — 카드당 5장 × 약 17KB라 감수한다. `LIST`(w342)는 과하다.

  *"영화 8편"* 인데 선반에 3장일 수 있다 — **정상이며, 빈 슬롯을 채우지 않는다**(M2-C §5.2:

**여기까지가 "컬렉션 목록 UI 미구현"의 실체였다.** 카드·토큰·선반은 9/9에 다 만들어져
있었고 채울 데이터만 없었다.

## 3. 드래그 순서 편집

### 3.1 라이브러리 — `react-native-sortables`

```
npx expo install react-native-gesture-handler
npm i react-native-sortables
```

| | |
|---|---|
| 버전 | **1.10.1** (최신 배포 2026-09-26) |
| `reanimated` | **3.x · 4.x 명시 지원** — 우리는 4.5.1 ✅ |
| `gesture-handler` | 2.x · 3.x — ⚠️ **미설치 → 설치 + 재빌드** |
| New Architecture | 지원 |
| **그리드** | **`Sortable.Grid` 지원** ← 컬렉션 상세의 그리드 모드에 필요 |

**기각 — `react-native-draggable-flatlist` 4.0.3**: 마지막 배포가 **2025-05**로 1년 넘었고
`reanimated >=2.8.0` 선언이라 **v4 호환이 미검증**이며, 무엇보다 **리스트 전용이라 그리드
드래그가 안 된다.**

⚠️ **`GestureHandlerRootView`로 앱을 감싸야 한다.** 빠뜨리면 **에러 없이 드래그만 조용히
안 먹는다** — 가장 흔한 함정이다. `App.tsx`의 프로바이더 스택 **가장 바깥**(`SafeAreaProvider`
바깥)에 둔다.

🔖 **폴백 — 라이브러리가 실기기에서 실패하면 `↑↓ 버튼` 방식으로 간다.**
항목마다 위/아래 이동 버튼을 두는 방식이며 **라이브러리 0개 · `gesture-handler` 불필요 ·
재빌드 불필요**하고, 스크린 리더에서도 동작한다(드래그는 불가). 수십 개 규모에서는 충분히
실용적이다. **이 폴백이 있으므로 라이브러리 리스크가 일정 리스크로 번지지 않는다.**

### 3.2 ★ 편집 모드를 분리한다 — 드래그와 무한스크롤을 공존시키지 않는다

| | 일반 모드 | **순서 편집 모드** |
|---|---|---|
| 목록 | 무한스크롤 | **전량 로드** |
| 드래그 | ❌ | ✅ |
| 툴바 접기 | ✅ | ❌ **끈다** |
| 탭 스와이프 | ✅ | ❌ **막는다** |

**이유 셋** — ① 화면 밖 항목으로 끌어다 놓을 수 없다 ② 드래그 중 페이지 로드가 겹치면
꼬인다 ③ **스크롤하려다 실수로 항목을 끄는 것**을 막는다.

- 진입: 헤더 `MoreVertical` → `ActionSheet`에 **`순서 편집`** 추가(M2-C에서 수정/삭제에 쓴 것)
- ~~전량 로드: `size=200`(컬렉션) / `size=500`(영화) — **서버 `@Size` 상한과 같은 값**~~
  → ⚠️ **한 번 요청으로는 불가능하다(2026-09-27 실측).** 서버의 `spring.data.web.pageable.max-page-size
  = 100`(백엔드 5-0-D)이 `size=200`을 **에러 없이 100으로 자른다**(`/api/movies?size=200` → `"size":100`).
  잘린 배열을 저장하면 집합 불일치 400이다. → **`size=100`으로 `last`까지 이어 받는다**(컬렉션 최대 2회,
  영화 최대 5회). 받은 개수가 상한(200/500)을 넘으면 진입을 막는다. 상수는 `src/constants/collectionOrder.ts`
- ⚠️ **상한을 넘는 사용자는 편집 진입을 막고 안내한다.** 현실적으로 없지만, 조용히 잘린
  목록을 저장하면 **나머지가 전부 날아간다**(서버는 집합 일치를 요구하므로 400이 나서 그
  자체로는 안전하나, 사용자는 이유를 모른다)
- ⚠️ **편집 모드에서 툴바 접기를 끈다** — 드래그 중 스크롤로 툴바가 움직이면 혼란스럽다
- 저장: **전체 배열을 한 번에**. 낙관적 업데이트하고 실패 시 **원 배열로 복원**
- 취소: 원 배열 복원

⚠️ **편집 중 뒤로가기 → 저장하지 않은 변경 경고.** `navigation.addListener('beforeRemove')`로
가로채 `Alert`로 확인한다.

> 💡 `beforeRemove`는 **§8.6에서 걷어낸 그 API**다. 그때는 *네이티브가 이미 하는 일을 JS로
> 재구현*하는 잘못된 용도였고, **여기서는 "떠나기 전에 물어본다"는 이 API의 본래 용도**다.
> 같은 API를 다시 쓰는 것이 모순이 아니라는 점을 적어 둔다.

**구현 (2026-09-27)**

- `hooks/useReorderMode.ts` — 두 화면 공통: `editing`·`order`(로컬 배열)·`dirty`·`start`·`finish`.
  저장 안 한 변경 경고는 **`usePreventRemove`**(`beforeRemove`를 native-stack에 맞게 감싼 공식 훅)로 했다 —
  `dirty`일 때만 막고, 변경이 없으면 뒤로가기는 그냥 나간다.
- `hooks/useCollection.ts` — `useLoadAllMyCollections`·`useLoadAllCollectionMovies`(버튼 핸들러에서 쓰는
  `fetchQuery`, `staleTime: 0` — 편집은 항상 서버의 현재 순서에서 시작), `useReorderCollections`·
  `useReorderCollectionMovies`. **변수는 id 배열이 아니라 새 순서의 항목 자체** — `onMutate`에서 무한스크롤
  캐시를 새 순서로 다시 잘라 넣는다(이미 받아 둔 개수만큼 새 순서의 앞부분으로 채움. 편집이 전량을 들고 있어
  아직 안 받은 항목도 채울 수 있다). 실패 시 스냅숏으로 롤백.
- 전량 로드 키는 `['collections','ofUser',userId,'all']`·`['collections','movies',id,'all']` — 기존 키의
  **접두사 아래**라 담기/빼기 등 기존 무효화가 그대로 함께 걸린다.
- 저장 실패는 **편집을 닫고** 알린다 — 롤백된 캐시가 곧 원래 순서다(§4.2-8). 취소도 같은 경로.
- ⚠️ **§4.2-10의 "탭 스와이프"는 해당 없다** — 컬렉션 화면은 `MyLibrary` 탭이 아니라 `MyPageStack`의
  독립 화면이다. 툴바는 편집 모드에서 **아예 그리지 않아** 접힘이 없다.

### 3.3 두 화면

**컬렉션 목록** — 선반 카드를 세로로 끈다.
- 편집 모드에서는 **카드를 간소화**하는 것도 방법이다(포스터를 끄고 이름만) — 드래그 중
  이미지 5장 × N개가 움직이면 무거워진다. 실기기에서 보고 판단한다.
  → **간소화로 시작했다**(`CollectionReorderRow`: 손잡이 아이콘 + 이름 + 편수, 테두리는 선반 카드와 같은

  없어 메뉴 하나짜리 시트를 새로 만들기보다 아이콘 하나를 두었다. `컬렉션 생성` 버튼은 그대로.

- **`Sortable.Grid`와 리스트 둘 다** 필요하다. 라이브러리가 그리드를 지원하는 것을 택한

- ⚠️ 복잡하면 **편집 모드에서는 그리드 한 가지로 고정**하는 것도 정당하다 — 순서를 보는 데는
  그리드가 낫고, 토글 두 벌을 유지할 값어치가 크지 않다.
  ~~→ **그리드 고정으로 구현**(`Sortable.Grid` 3열, 셀은 `PosterImage`만). 진입은 기존 `ActionSheet`의
  **`순서 편집`**(2편 이상일 때만).~~

  - ⚠️ **잠복 버그 수정** — 모달이 새로 담은 영화를 **목록 끝**에 보여 줬는데, v17 서버는 요청 순서대로
    `MIN-1, MIN-2…`로 넣어 **나중에 고른 것이 맨 위**가 된다. 저장 전 화면과 저장 후 순서가 달랐다 →
    담으면 **맨 앞**에 넣는다.
  - 모달의 "닫기"는 원래 설계대로 **묻지 않고 전부 취소**한다(§3.2의 저장 안 한 변경 경고는 컬렉션 목록의
    순서 편집에만 남는다). 500편 초과면 드래그만 끄고 담기·빼기는 그대로 된다.
  - 영화 순서 저장 훅(`useReorderCollectionMovies`)은 **낙관적 업데이트를 뺐다** — 저장 직후 모달이 닫히며
    무효화로 다시 받고, 모달의 항목은 상세 목록 응답 필드(개봉연도·감독)를 다 갖고 있지 않다. §3.4의
    이중 무효화는 그대로.

  `영화 편집`, 상세 경위는 `M2C-screens-spec.md` §5.3-A). 전량 로드·저장 순서(추가 → 삭제 → 순서)·"새로 담은 것은
  맨 앞"·500편 초과 시 드래그만 끔은 그대로. 바뀐 것: ① **3열 그리드 → 1열 리스트**, 길게 누르기 → **≡ 핸들**
  (`customHandle`), X → **⊖ 탭 / 왼쪽 스와이프 → 삭제 버튼** ② 스택 화면이라 `GestureHandlerRootView` 재포장 불필요
  ③ 저장 안 한 변경이 있으면 뒤로가기 때 **묻는다**(`usePreventRemove`) — 모달의 "닫기 = 묻지 않고 취소"는 폐기.
  → **같은 날 이어서: 전량 로드를 진입에서 `저장` 시점으로 옮겼다.** 편집 화면은 상세의 무한스크롤 캐시로 시작해
  스크롤하며 이어 받고, 순서를 바꾼 경우에만 저장 때 전량을 받아 **화면에 없는 뒷부분을 서버 순서대로 끝에** 붙여
  보낸다. §3.2의 "편집 모드는 전량 로드"는 컬렉션 **목록** 순서 편집에만 남는다(카드가 가벼워 이득이 작다).

### 3.4 ★ 무효화 — 영화 순서가 카드 포스터를 바꾼다

| 액션 | `invalidateQueries` |
|---|---|
| 컬렉션 순서 저장 | `['collections','ofUser',userId]` |
| **컬렉션 내 영화 순서 저장** | `['collections','movies',collectionId]` · **`['collections','ofUser',userId]`** ← ★ |

★ **미리보기 포스터가 `position ASC`이므로, 영화 순서를 바꾸면 카드에 보이는 5장이 바뀐다.**
상세만 무효화하면 뒤로 나갔을 때 **카드가 옛 포스터를 들고 있다.**
M2-C의 `movieCount` 함정(§3.1)과 **똑같은 구조**다 — 목록 응답에 상세의 파생값이 들어 있다.

| # | 확인 |

**14번을 빠뜨리지 않는다** — 제스처 라이브러리가 네비게이션 제스처와 겹칠 수 있다.

## 5. 하지 않을 것

- **`CollectionSort` 정렬 옵션** — 드래그가 유일한 순서다(백엔드 5-4-A ①에서 확정)
- **`B-7` 컬렉션 단건 조회** — 딥링크가 없다. **소셜(3군)에서 남의 컬렉션에 들어갈 때** 필요해진다
- **컬렉션 간 영화 이동** — 드래그로 다른 컬렉션에 떨어뜨리기. 범위가 훨씬 크다
- **순서 편집의 undo** — 취소(전체 복원)로 충분하다
